## 4. Files that MUST NOT enter a release

| Category | Paths | Reason |
|----------|-------|--------|
| Secrets | `.env`, `laravel/.env` | Credentials; use `.env.example` only |
| Dependencies | `node_modules/`, `laravel/vendor/` | Rebuilt via `npm ci` / `composer install` |
| Build output | `dist/` | **Gitignored** (`.gitignore` line 10); generated by `npm run build` on deploy host |
| Vite cache | `.vite/` | Gitignored; ephemeral |
| PHPUnit cache | `laravel/.phpunit.result.cache` | Gitignored; local test artifact |
| IDE / local | `.cursor/`, `*.log`, `*.bak` | Gitignored |
| OS junk | `.DS_Store` | Gitignored |

### `dist/` policy

- `dist/` is listed in `.gitignore` and **must not be committed**.
- Production/staging deploy should run `npm run build` on the target host (see `deploy/deploy.sh`).
- If `dist/` appears as untracked in `git status`, **do not** `git add dist/`; document as expected ignore behavior.

## 5. How to create a release branch (when Owner instructs)

**Prerequisites:** Working tree reviewed; no secrets in staged files; `php artisan test` and `npm run build` pass on the machine creating the release.

```bash
# 1. Ensure you are on main (or agreed integration branch)
git branch --show-current

# 2. Review what will be included
git status
git diff --stat

# 3. Create release branch from current working tree state
git checkout -b release/sprint19-2026-08-28

# 4. Stage intentionally (exclude dist/, .env, caches)
git add laravel/ src/ deploy/ docs/ .env.example laravel/.env.example package.json package-lock.json index.html vite.config.ts tsconfig.json .cursorrules SPRINT19_EXECUTION_REPORT.md
# Add other root config files as needed; NEVER git add .env or dist/

# 5. Verify staged set
git diff --cached --stat

# 6. Commit (only when Owner explicitly requests)
# git commit -m "Release baseline: Sprint 4–19 accumulated work for staging verification"
```

**Do not push** until Owner approves remote and target environment.

## 7. Rollback commit strategy

| Scenario | Action |
|----------|--------|
| **Bad deploy, code only** | `git checkout <previous-release-sha>` on server; `composer install --no-dev`; `npm ci && npm run build`; reload php-fpm/nginx/supervisor |
| **Bad deploy + DB migration** | **Prefer** restore from pre-deploy MySQL snapshot (see `docs/PRE_DEPLOY_SNAPSHOT_RUNBOOK.md`). Migration `down()` only if safe and reviewed. |
| **Release branch abandoned** | `git checkout main`; delete local `release/*` branch; do not force-push `main` without Owner approval |
| **Never use** | `git reset --hard` on shared branches without Owner approval; `git clean -fd` on deploy servers with local uploads |

Record every rollback: git SHA before/after, migration batch, snapshot file used, operator, timestamp.
